## 启动与试玩

在项目目录执行 `npm run cards`，打开 http://127.0.0.1:7460/ 。服务只在本机监听，终端需要保持运行；可用环境变量 `CARD_EDITOR_PORT` 修改默认端口。

首次试玩或修改游戏脚本后，先执行 `npm run build:web`。随后通过网页顶部的「试玩游戏」打开真实 COCOS 对局。以后仅修改卡牌数据时，点击「保存并试玩」即可在新对局读取最新数据，不需要反复构建。

已经开始的对局保持原配置，试玩窗口的「重新载入」会开始新对局。独立游戏预览和发布版本使用随构建打包的配置，发布前仍需正常构建。

## 新增与编辑

1. 点击卡牌库旁的「＋」新增，或选中现有牌点击复制按钮。
2. 填写名称和唯一 ID。ID 为小写字母开头的 2～48 位字母、数字、下划线或短横线，保存后保持稳定。
3. 修改费用、重量、现有插画、标识色与补充说明。主要效果说明由配置数值自动生成，卡名使用标识色衍生的可读深色字。
4. 选择伤害、格挡、修复，或装备生成指定临时牌的效果。装备从下回合起生效，仍占用唯一武器槽。
5. 设置初始携带数量、随机奖励池标志和固定搜刮奖励，让新牌进入游戏。
6. 点击「保存到项目」或按 Ctrl+S，也可以直接「保存并试玩」。保存后刷新网页仍能读到修改。

初始负重包含 10 点物资，上限为 30。底部统计与错误提示会显示非法数值或超重。修复仍受护甲上限和感染临界限制。中毒、召唤等新机制需要先扩展规则代码。

普通牌可设为临时牌；临时牌重量为 0，不进入初始卡组或奖励池，可由装备生成。

## 删除与引用保护

普通牌删除时会一并移出初始卡组与随机奖励池。作为固定搜刮奖励、或被装备生成关系引用的牌，需先更换引用。奖励池至少保留一张普通牌。

基础攻击、基础躲避、现金和系统挥砍不能删除或更改身份。基础能力保持免费、零重量和至少一张初始数量，现金保留一张初始遗物；可在允许的字段范围内编辑名称、插画和效果参数。

## 保存与恢复

数据实际写入 `assets/resources/data/cards.json`。保存前校验全部配置并检查修订号，自动备份上一版后原子替换文件；无效数据和冲突不会破坏旧文件。

其他页面或程序更新文件后，保存会提示冲突。先保留自己的修改内容，再「重新载入」并合并，避免覆盖别人的更新。未保存的页面有离开提醒。

备份位于 `temp/card-editor-backups/`，文件名包含时间。恢复前先保留当前 JSON，再选择需要的备份覆盖配置，回到网页重新载入并核对。备份和构建产物不提交到 Git。

## 检查

`npm test` 执行规则和保存服务测试。浏览器验收驱动在 `tools/browser-card-editor.js.txt`，包装器为 `tools/run-card-editor-test.cjs`；驱动会创建、保存并删除实际项目中的测试牌，应在专门测试窗口运行，避免同时编辑。

验证记录见 `docs/card-editor-verification.md`，结构化结果和截图位于 `output/`。

## 已实现的规则

| 进入档位 | 入场物资点 | 每回合体力 |
| --- | ---: | ---: |
| 紧急 | 0 | 1 |
| 低投入 | 4 | 2 |
| 标准 | 8 | 3 |
| 高投入 | 14 | 4 |

出发前可比较档位，只有确认出发才扣一次入场费。取消不扣费，负担不起的档位禁用。建议选中的档位按余额优先标准、其次低投入、否则紧急；玩家可以自行选择可支付的档位。这一默认选择属于界面行为，不替代玩家确认。

每场战斗与每个玩家回合开始时，将体力重置为该档位的上限；结束回合时余量清零，不累积。卡牌费用由战斗体力支付，0 费卡在体力为 0 时仍可使用，规则不允许的卡不能提前扣费。取消拖牌或只选择攻击目标不扣费，实际命令执行时才支付。

物资点与体力独立。物资点不占探索负重，不能通过丢弃物资点释放卡牌空间；实体卡牌与物品仍占负重，暂存与自动转入沿用当前规则。入场已支付后，不再叠加教学搜刮节点的 2/3 点费用，也不因在地图内物资点为 0 自动判定教学式资源耗尽失败。

修复仍检查能否支付修复本身。修复后不足每日需求时显示风险，玩家可以取消，也可以确认修复；每日 1 点需求只在结算最后支付，不够时记录缺口，余额最低为 0。

## 职责与原生接入

- `core/content/EntryTiers.ts` 保存档位内容与查找，`GameScenario.ts` 区分新的 `stamina-v1` 和保留的 `tutorial-v1`。
- `ExplorationRules` 处理入场资格和扣费；`CombatRules` 处理体力、卡牌费用和回合；`InventoryRules` 处理独立物资点与物品负重；`SettlementRules` 保持修复和每日结算。
- `GameSession` 是命令与保存入口。`UiActionRouter` 的档位比较只改 `UiState`，确认才发送带 tier 的 start 命令。
- `EntrySelection` 与 `EntryTierPopup.prefab` 承载四档选择；`TheEnd.scene` 通过稳定容器绑定第六个 popup。`BattleScreen.prefab` 的 `StaminaGauge` 显示剩余/上限及每回合预算。
- 手牌、背包、奖励和本地卡牌编辑器统一显示实际体力费用；兼容旧规则的卡面仍显示物资，避免显示与规则不一致。

普通构建不执行资源编写工具。新增界面资源经 Pink 导入保留元数据，显式作者入口为 `tools/build-deck-map-ui.cjs --entry-popup` 和 `--connect-stamina`。

## 保存与兼容

新开局默认使用 `stamina-v1`。档位、当前体力与体力上限进入存档；读取时核对当前档位与战斗预算，重载不会授予一个新回合的体力。存档封套仍用现有 v1 格式，通过 scenarioId/version 区分规则；旧战斗缺失的体力字段规范为 0。

旧存档继续原 `tutorial-v1` 规则，并提示“重开新探索后启用体力系统”。不把进行中的旧对局静默改成新经济规则。玩家确认重开后，新局改用体力；不清空用户浏览器资料来测试迁移。

## 保持待设计的部分

现有固定 A/B 内容、第 2 天兼容终点、护甲/敌人数值和失败重置依然是当前内容范围，不自动成为正式版永久约束。首回合 4/3 抽牌的组合解释、仓库、物资卡兑换、配方、长期成长、正式失败代价和多日循环不在本次实现。

兼容关卡仍直接给予物资点奖励，尚未改为“带回物资卡后按待定价格兑换”的完整经济系统。未为填补这处设计空白擅自设置兑换价格。当前可执行卡库仍为 `assets/resources/data/cards.json`，没有把仅供组件预览的正式参考卡表替换进来。

## 美术与界面复查

体力接通后，复看真实引擎画面中的 08 人物、三张 v2 背景、脚底接触影、卡纸、背包、奖励、路线地图和 1024×768 窗口。修正背包提示压标题、主地图提示压纸面标题，以及旧文案错误暗示物资点占负重的问题。

地图节点沿用原生 Graphics，补上同色系简笔色块和可辨识的骷髅、焊接面罩、篝火、补给箱、避难所；保留可到达/完成/另一条路径的原资格。没有导入参考游戏美术，没有放大人物，也没有将静态截图写成动作自然程度的认可。

本轮技术验证、执行者对实际画面的观察和用户最终视觉认可分别记录。其他动作仍使用既有资源，不以本次体力与界面修改宣称新绘多帧动画完成。

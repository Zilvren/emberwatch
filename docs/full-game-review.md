**牌序例子**　先出滑步和折光屏，已有至少 4 格挡时，返压由 3 伤害提高到 6，格挡仍在。先出免费的压掌再用追波，追波由 2 伤害提高到 6。开匣占用体力并抽牌，玩家要在补手和当回合输出之间取舍。

**平衡样本**　用 1–64 号种子跑了 512 次已配置的路线、档位与策略组合。紧急档闸脊线上，优先输出的脚本完成 49/64，先防再攻完成 64/64。标准档同一路线两种脚本均为 64/64，成功返家时平均护甲分别为 4.70 和 9.52。这说明体力档位和对意图的处理会改变损耗。适用对象是首张地图，真人选牌偏好与多日重复游玩的节奏仍需实测。

## 结论与边界

当前实现可以完整走通首次探索：日志、固定搜刮、A/B 路线、两场战斗、搜刮、营地、返家、修复和每日结算、第 2 天教学终点，以及失败重试。它具有进度保存和恢复，但还不是完整正式版。设计稿中的体力、持续多日、仓库、制作、蓝图和遗物等不能作为已实现内容评价。

本轮保留场景优先构图、08 人物造型与比例、既有教学数值和规则。在最终验证的 Web 桌面范围内，没有再发现需要立即修改的实质性问题。这个结论不表示绝对完美，也不代替用户最终美术认可或真实玩家测试。

## 仍需后续处理或用户取舍

| 优先级 | 待项 | 原因与下一步 |
| --- | --- | --- |
| 正式版 P1 | 持续多日、撤离、失败代价、仓库/体力与跨局成长的首个可玩闭环。 | 原设计稿仍含提案。应先确认一个正式切片的规则和范围，再实现与实测经济；不能靠改掉“第 2 天结束”文案视为完成。 |
| 正式版 P1 | 内容与长期平衡。 | 25 张定义、8 类敌人等属于内容草案，当前运行库与敌人数值仍是教学版本。需要正式内容真实接入后的玩家测试，当前不应随意换数值。 |
| 美术 P2 | 非待机角色动作、最终场景分层与音效制作。 | 现有待机与原画比例保留；未逐帧艺术定稿全部动作，也未完成最终混音评审。下一步应对攻击、受击、死亡各做一段单独评审样片，继续保留 08 造型。 |
| 平台 P2 | 完整键盘/控制器核心操作、触屏和移动端重排。 | 本轮验证 Web 桌面鼠标与弹窗键盘；1024×768 等比适配不是手机适配。现有手牌仍以点击、拖拽、长按为主要操作。 |
| 验证 P2 | 真实玩家首次游玩、长时间稳定性和更多随机种子。 | 自动操作与审稿不能替代玩家学习成本、内容重复感和性能测量。正式发布前补充这部分证据。 |

这些待项是明确保留的范围和验证限制，不是已确认的新玩法，也没有被本轮报告宣称完成。当前交付可以继续由用户评审整体美术，并选择正式版下一阶段。

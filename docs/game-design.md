## 2. 游戏定位与体验目标

**已确认方向**：单人末日生存卡牌，文字日志与场景叙事结合；通过整备、探索、看意图出牌和选择撤离管理风险。

**提案**：一次地图探索约 8–15 分钟；完整章节由多次出发构成。主要乐趣是用有限投入拼出可生存的战术，并在眼前收益和安全带回之间作选择。操作重点是判断与准备，保持回合制，不增加即时反应门槛。

三个体验支柱：

1. **世界先于面板。** 角色与环境承担视觉重心，UI 贴近资源、目标与操作，不把场景缩进后台窗口。
2. **风险可以理解。** 敌人意图、入场费用、容量、临界状态和不可逆损失事前说明，不用隐藏惩罚制造难度。
3. **带回才有意义。** 探索所得支持下一次选择；基础能力和长期解锁保持清楚的保护边界。

## 3. 世界与目标

**叙事提案**：幸存者守着一处失去对外联络的避难所。收音机里的残余信号指向旧城区、废弃工厂和远端中继设施。玩家逐步获得线索、蓝图和必要设备，最终修复可联络的中继站。

**首轮完成条件提案**：带回关键部件并完成最后的中继任务，留下完成记录；之后允许继续探索。天数体现生存压力，不设置没有提示的固定天数猝死。探索失败不等于删除整份长期进度。

角色继续使用已选 08 的幸存者、游荡感染者和重型感染者。已有造型、配色与显示比例保留；新增敌人另作剪影和动作设计，不能靠只改颜色交付不同战术类型。

## 4. 完整日循环

**2026-11-16 已确认更新**：关键日志 → 整备与进入档位 → 地图探索 → 正式探索成功或失败均过一天 → 有新关键日志则显示，否则返回避难所。取消每日结算及每日生存物资消耗；教学失败仍第 1 天。正式失败恢复既有初始补给、牌组和护甲，保留天数与日志进度。实现见 designs/key-node-journal-system.md。

具体交互提案：

1. 日志显示关键节点触发时的实际天数与固定文案；相同节点可在不同玩家的不同日期触发，普通日子不显示日志。
2. 玩家选择出发或留守。出发前清楚显示入场费用、每回合体力、携带容量和允许的地图档位。
3. 从仓库选择本次带入的实例，并确认其中哪些有战斗资格。物品携带与是否抽入战斗分别处理。
4. 在地图节点间选择搜刮、战斗、休整或事件；每一步看到可能收益、危险与容量影响。
5. 在地图的可操作节点可主动撤离。提案基线不允许在敌方出手中直接无代价逃离战斗。
6. 返回后按序处理带回、兑换、制作、升级与修复；同一次返回不能重复入库或重复领奖。
7. 返家可按实际费用修复，取消每日消耗及余额预测；主按钮为整备出发。
8. 地图结果产生时过一天并保存，关键日志由进度条件与前置日志触发，不以固定日期或教学第 2 天为终点。

物资不足以支付**修复本身**时不能修复。每日需求不足仍保留现有的实际支付、缺口记录与非负余额规则。本稿没有把预留每日物资改成强制限制。

## 6. 战斗规则

### 6.1 回合

敌人先给出意图 → 玩家回合开始 → 刷新体力 → 武器按规则生成牌 → 抽牌 → 玩家出牌 → 玩家结束回合 → 敌人执行意图 → 清理当前回合状态。

**抽牌解释提案**：战斗开始抽 4 张，首回合不再额外抽 3；从第二回合开始抽 3，手牌上限 6。回合结束未打出的普通牌进入弃牌堆；抽牌堆为空时重洗弃牌堆。生成牌优先占位，手牌已满时未能抽出的普通牌留在抽牌堆，不直接销毁。原表给出了 4/3/6，叠加方式与回合末处置在这里补为提案。

### 6.2 护甲与临界

护甲降至 0 进入感染临界；再次受到**实际正伤害**才结束战斗，完全格挡不触发。修复牌在护甲 0 时不能使用。返回避难所解除当前感染临界，护甲修复仍独立处理。保留当前完整修复基线：护甲完整为 0 费，受损为 1，曾处于临界为 2；正式经济调优时单独评审数值。

**多段伤害提案**：逐段扣格挡、扣护甲和检查临界；同一招的后续正伤害也可以击败已临界角色，因此意图必须显示次数和每段数值。未设计的连击不会仅凭卡牌文字自动执行。

## 7. 地图、搜刮与撤离

**地图开放提案**：旧城区开放紧急/低投入；工厂开放低投入/标准；中继区开放标准/高投入。档位只决定整张地图的体力，不在地图内靠付点数临时提档。

紧急档采用旧城区外沿的短路线提案，最多 3 个节点、预期带回兑换值 2–4；它提供自救，不免费享有完整路线的全部收益。同一内容的奖励不因多付入场费而暗中翻倍，高收益来自对应地图内容与危险。初始整备提案为物资 10、基础攻击/躲避各 2 张，加菜刀、修复、强化躲避、重击各 1 张；基础牌不作为可重复奖励或制作产物，避免零重量复制绕过构筑约束。

**搜刮危险提案**：可见危险 0–6；常规搜刮 +1，追加翻找 +2。达到 4 时明确预告强化遭遇，达到 6 后需要处理已预告的遭遇才能继续搜索。不在领取奖励后突然生成未提示的惩罚。危险不再伪装为消耗避难所物资点。

路线由配置与种子生成并保存；玩家看到有限的后续信息，局外遗物可扩展信息范围。搜刮、战斗、休整和事件都有明确收益与成本，不能用只写一段文字的空节点填充正式地图。

战斗战利品提案保留三选一普通卡与物资类奖励独立领取。搜刮可给 1–3 件物品，玩家按容量挑选。暂存物品不能抽入战斗，释放基础容量后按确定顺序转入。离图前确认仍在暂存区的物品将失效。

## 8. 失败、保护与保底

以下是**正式失败代价提案**，尚未修改当前失败全量重置：

- 基础能力、局外遗物、已解锁信息与仓库中未带入的东西不丢失。
- 出发前提供 2 个保护位，只能保护既有带入实例；其余风险区物品（包括未带回的新物品）在失败时丢失。
- 入场费不返还；局内遗物清除；返回避难所记录原因，长期进度与天数不整体重置。
- 具体损失在出发、保护位选择、濒临失败与失败结算中使用相同规则说明。

**防软锁提案**：紧急档与可重复的避难所“回收废料”主行动保证有恢复路径；回收基线获得 2 点物资，推进一天并在最后支付每日消耗。它不自动给装备或解除所有失败代价。广告救济不进入核心闭环，也不用于掩盖经济无法自救的问题。

## 9. 仓库、兑换、制作和升级

仓库无限容量，但探索携带仍有限；归还和仓库写入以一次返回事务为单位，重复点击不能重复入库。定义、实例、堆叠显示与数量扣减分别处理。

**经济初始提案**：小型补给物资卡重量 1/兑换 2，补给箱重量 3/兑换 6，整箱储备重量 6/兑换 11；绳子重量 2/兑换 1，材料电池重量 1/兑换 2。以上不是原表已定数值。低投入地图预期安全带回兑换值 7–9，标准 14–17，高投入 24–29；扣门票、每日和修复后再评估净收益，不能只比较毛掉落。

制作前先取得对应蓝图。未解锁时不显示配方与材料列表；解锁后显示产物、材料、物资消耗及成品是否可入战斗。确认制作时统一检查资源，成功后原子扣除并生成实例，失败不留下半成品。

**升级提案**：在避难所升级特定实例，首版普通卡每张最多 1 级。效果加 1 或费用调整按明确升级表配置，不让自由文本直接生效；不默认修改所有同名卡。基础牌是否允许升级保持单独评审，首版提案不开放其永久数值叠加。

## 10. 遗物、蓝图与内容成长

局外遗物优先提供信息、功能、解锁和规则改变。例如地图侦察范围、记录完整敌人意图、打开新的整备方式；不把长期成长默认做成永久攻击力堆叠。局内遗物可以支撑本次探索的战术变化，并在探索结束时清除。

**首个正式切片内容提案**：3 张地图、8 类敌人、25 张卡牌/物品定义（含材料和战斗临时牌）、12 个事件、6 张蓝图、6 个局外遗物与 8 个局内遗物。具体名称、效果、费用、重量、配方与事件选择已列入 designs/formal-content-draft.json，并检查配方与生成牌引用。现金单列为兼容教学物品，不计入 25 张正式定义。先用一张地图与完整回家闭环验证，再扩数量。现有素材和运行效果没有达到这些数量，不把设计清单当成已完成实现。

日志记录角色的处境与行动后果。事件至少给出可理解的选择、即时结果与长期影响；缺少某种物品时显示可见资格，不用让玩家反复点失败按钮来猜条件。

## 11. 场景、人物与 UI

**用户已确认的美术约束**：08 的人物造型、配色、服装装备和原显示比例；细描边，浅土黄、灰橄榄、淡棕色。不能为了做新页面重新生成一套不一致的人物。

**已明确否决**：后台式固定侧栏、大面积色块、把游戏拆成 PPT 展示板。独立组件评审图不代表完整游戏页面，也不能以构建成功代替美术通过。

当前场景优先候选：全屏世界、贴边 HUD、靠近对象的信息、底部实体感手牌；先统一人物、背景与材质。背景使用细线手绘和有限阴影层，远景比人物更低对比，照明方向和地面接触一致。卡牌是旧纸/帆布，操作钮可表现磨损金属或皮革，避免混用像素、写实贴图和扁平办公组件。

视觉验收提案：角色脚底落在同一可解释的地面平面；接触阴影相连；门窗尺度不让人物像巨人；头像与名牌不互相遮挡；重要文本能读清；抬牌不遮住敌人意图；鼠标、触控和键盘都能完成核心动作。

角色待机保持脸、脚底和装备轮廓稳定。当前固定原画呼吸已验证；其他动作仍需逐项评审。生产方案优先保证连续骨骼/网格或逐帧造型一致，再确定帧数，不能靠增加独立生成图片解决变形。攻击必须有准备、接触、收势，命中事件只结算一次；死亡完成后才进入结果页。

音效采用纸布摩擦、轻金属、脚步、风和低量广播噪声；数值不为装饰滚动。减少动态效果时关闭环境漂移和镜头位移，保留动作结果可读性。当前程序音效和单层背景不等于最终混音、分层场景与全部正式动画已经交付。

## 12. 页面与操作

日志、地图、战斗、战利品、营地、避难所、背包、工作台与长期收藏各有明确职责。主场景以世界为中心，背包/配方等需要精确阅读时可以覆盖打开，但关闭后回到原操作对象与焦点。

取消拖动、移出按钮松开、关闭详情都不扣资源。危险删除要显示实际实例名称与后果，默认焦点在取消。按钮的禁用状态同时说明原因。牌的名称、费用、关键词、主效果和重量具有稳定信息层级，长说明使用可读详情。

当前临时战斗预览可从显式 seed + save=off 入口直接到首场遭遇；这是开发查看入口，不是正式玩家绕过日循环的流程。普通入口继续恢复实际进度。

## 13. 数据、存档与工程

保持 core 纯规则、application 命令、infrastructure 存储和 presentation 引擎表现分层。UI 读取只读模型，经命令层执行规则；动画事件负责表现时机，不持有一套独立游戏数值。

正式状态需明确区分战役、仓库、一次探索和一场战斗；保存实例 ID、章节、随机状态、进入档位、领取标记和交易标记，不保存 Node/SpriteFrame。卡牌定义在一次探索开始时冻结，网页编辑器的新配置不能悄悄改变正在进行的战斗。

版本变更提供校验、可迁移版本与不支持版本的保护。主存档损坏使用上一份有效备份；不兼容时保留原始数据并说明原因，不自动覆盖成空白。返回、消耗品、制作和升级用稳定事务 ID 防止中断后的重复结算。

初始发布平台提案为 Web 桌面，移动端、桌面原生和控制器需要各自验证。真实场景、Prefab、AnimationClip 与数据工具必须能在 Pink 中查看和编辑，不能只交付运行时临时拼图。

## 14. 实施顺序与验收

1. 确认整屏构图与 08 美术协调，完成一屏真实战斗及菜单/结果状态的视觉评审。
2. 评审本稿未确定提案，建立正式内容模型与独立情景版本，不破坏兼容回归。
3. 实现仓库、进入档位、体力与可持续日循环，覆盖返回和失败恢复。
4. 加入蓝图、制作、实例升级及遗物，先完成最小内容切片再扩数量。
5. 用实际游玩校准收益、失败、保护与自救，检查高档位是否既有价值也有风险。
6. 完成各平台输入、画面、存档、性能和可恢复交付。

当前仍按用户要求先做画风、整体 UI 与架构，不把步骤 2–6 中的新运行流程当作已经授权实施。78 条现有测试和 A/B 实机回归只证明当前兼容内容；正式设计落地后需要相应的规则与恢复验收。

待评审的核心提案为：搜刮危险阈值、失败保护位/损失范围、兑换价值、材料堆叠、地图档位限制、留守自救及章节完成目标。此稿已给出一套相互衔接的基线，避免把空白项伪装成确定规则；最终数值由评审和正式切片游玩决定。
